# Строки ГОСТ для обучения и независимой проверки

`prepare_manifest.py` фиксирует заранее заданные значения в `docs/test-samples/gost-type-a/corpus-plan/manifest.json`. `render_lines.py` читает именно этот SHA-256 и создаёт отдельные PNG + UTF-8 `.gt.txt`, не обращаясь к OCR. Содержимое эталонов после результатов распознавания не меняется.

Первый пилот использует только обозначение и наименование. Два стандартных названия вида документа повторяются между частями исходного manifest, поэтому они исключены из независимого испытания строк. Внутри каждой части сохраняются все варианты одной строки; одинаковые строковые значения между `train`, `development` и `evaluation` запрещены. Проверяется также отсутствие полных исторических контрольных строк в обучении. Само слово Epcos встречается в новом обучающем наименовании; проверка старого `Плата Epcos USB` остаётся регрессионной, а не независимой проверкой незнакомого бренда.

Обучение и выбор настроек используют SkiaSharp 2.88.9 с закреплённым TTF. Итоговые строки рисуются Pillow/FreeType, тем же шрифтом и с другими DPI. Размер рассчитывается по фактической высоте кириллической `Н`: 5 мм для обозначений и 3,5 мм для наименований. PNG имеет один 8-битный канал и белые поля 16 пикселей. Обучающие варианты: 200/300 DPI без перекоса, 200 DPI −0,4° и 300 DPI +0,4°. Отдельно записываются число изображений и число уникальных текстов: варианты одной строки не являются новыми независимыми эталонами.

Нужны .NET 10 и Python с Pillow. Нативный OCR, Tesseract и Paddle для генерации не загружаются.

```bash
dotnet build tools/GostCorpus/GostCorpus.csproj -c Release
python3 tools/GostCorpus/prepare_manifest.py --check
python3 tools/GostCorpus/render_lines.py --split train
python3 tools/GostCorpus/render_lines.py --split development
python3 tools/GostCorpus/render_lines.py --split evaluation
```

По умолчанию результат лежит в `artifacts/gost-corpus/<split>/`. `--output` меняет корневую папку, `--dotnet` задаёт путь к .NET, `--skia-dll` — путь к собранному помощнику. Папка выбранной части должна быть пустой: скрипт не перезаписывает эксперимент. `lines.json` каждой части содержит массив `Lines` с `Id`, `CaseId`, `Role`, `LineIndex`, `Text`, `FullFieldExpected`, относительными `File` / `GroundTruthFile`, параметрами, размерами и хешами PNG/GT. Хеш manifest и шрифта, версии библиотек и проверки разделения записаны в том же JSON.

В обучение и early stopping передаются только `train` / `development`. `evaluation` проверяется после фиксации модели. Примеры в `docs/test-samples` не перезаписываются, исходный шрифт и его лицензия не меняются.

## Отдельное дополнение алфавита

До обращения к итоговым результатам зафиксирован `alphabet-supplement-v2.json`: 160 новых строк для обучения (128 обозначений и 32 слова с номером), покрывающих все 33 заглавные русские буквы, цифры, точки и дефисы. Префиксы и полные строки не повторяют основной корпус или исторические эталоны. Буква `Ё` находится в словах: действующая грамматика обозначений её не принимает. Это дополнительное обучение тому же шрифту, а не новый шрифт для независимой оценки.

```bash
python3 tools/GostCorpus/prepare_alphabet_supplement.py
python3 tools/GostCorpus/render_alphabet_supplement.py
```

Результат по умолчанию: `artifacts/gost-alphabet-v2/train`. Дополнение не подмешивается в первый пилот автоматически; решение о его использовании и хеши нужно явно записать в отчёт обучения. Основные train/development/evaluation и frozen manifest v1 не изменяются. Если итоговая оценка уже использована при настройке, она больше не является независимой для следующего кандидата.

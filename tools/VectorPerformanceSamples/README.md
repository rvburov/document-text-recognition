# Генератор отдельного векторного benchmark

Из корня репозитория на поддерживаемом окружении с PDFium/OpenCV/Skia:

```sh
dotnet run --project tools/VectorPerformanceSamples -c Release -- \
  docs/test-samples/vector-performance
```

Целевая папка должна быть новой или пустой. Генератор ничего не удаляет и не перезаписывает.
Старые `docs/test-samples/scans`, `templates`, `verification.json` и растровые результаты
не изменяются. Проект использует `GostTypeASamples.CreatePair` из `Core.Tests` и требует
закреплённый шрифт `tests/Core.Tests/Fonts/GOST2.304-81TypeA-Slanted.ttf` с проверкой SHA-256.
OCR-модели и обучение для генерации не нужны; настоящие движки при генерации не создаются.

Фиксированы четыре одностраничных случая: спецификация с переносом строки, спецификация
с латинскими `Epcos`/`USB`, сборочный чертёж и электрическая схема. Обозначения начинаются
с четырёх кириллических букв. Ожидаемые имена заданы строковыми константами до отрисовки
и проверки PDF. В именах явно сворачиваются пробелы и `ё→е` / `Ё→Е`; исходный текст сохраняется.
Все случаи имеют `RecognitionRequired=true`, независимо от будущего ответа распознавателя.

Выход:

- `scans/*.pdf`: четыре видимых векторных PDF со встроенным ГОСТ-шрифтом и Unicode-текстом;
- `templates/*.pdf` и `.pdf.template.json`: два общих шаблона по геометрии с посторонними
  значениями `ОБРЗ.000000.000`, `Образец`, `Тип документа` и сохранёнными координатами;
- `paired-raster/*.pdf`: отрисовка тех же страниц при 250 DPI без текстового слоя для аудита;
- `verification.json`: frozen truth, ожидаемые имена, SHA-256 PDF/разметки/шрифта, координаты,
  связь vector/raster и точная проверка текста внутри областей;
- `README.md`: классификация набора и границы результатов.

Генератор проверяет сохранённые области, извлечение точного Unicode-текста по этим областям
и отсутствие текстового слоя у растровой пары. Положительный итог генерации относится к
целостности макетов. Он не означает успешное OCR или допустимость быстрого пути: для этого
настоящая программа должна независимо прочитать видимые пиксели и подтвердить все поля.
Успех зависит от поставленных базовых/GOST OCR-моделей; отказ остаётся ошибкой проверки.

После подготовки набора короткая проверка настоящей программы выполняется отдельно:

```sh
dotnet run --project tools/Performance -c Release -- \
  --samples docs/test-samples/vector-performance \
  --count 4 --workers 1 --profile-passes 0 \
  --pdf-text true --gost-fallback true \
  --dataset-kind vector --expect-source pdf-text-confirmed --require-provenance true \
  --label vector-smoke --output artifacts/performance/vector-smoke.json
```

Временной результат вектора сравнивают с вектором, а старого image-only набора — с растром.
Новый набор не заменяет растровый baseline и не доказывает ускорение 8000 различных сканов.
Это синтетические регрессионные примеры из известного ГОСТ-исследования, а не независимая
итоговая выборка для оценки обученной модели. Логические строки и геометрия фиксированы;
байтовая повторяемость PDF между запусками не заявляется, реальные байты фиксируют SHA-256.

# Воспроизводимый замер OCR

Консольный инструмент запускает настоящий `OcrRenameRun`: загрузка шаблонов, PDF, совмещение,
чтение и сверка полей, переименование. Фактические ветки PDF-text/OCR записываются отдельно:
проверенный текстовый слой подтверждает растровый peer; сканы читаются OCR. Подмен
распознавателя и кэша ответов нет.

Набор — копии четырёх положительных PDF из `docs/test-samples` и три сохранённых шаблона.
Каждая копия лежит в отдельной подпапке, чтобы одинаковые распознанные имена не конфликтовали.
После замера проверяются все имена и SHA-256 каждого PDF. Подготовка копий и проверка хешей
не входят во время обработки. Это повторяемые синтетические одностраничные документы на
локальном диске; они не представляют 8000 различных производственных сканов.

```sh
dotnet run --project tools/Performance -c Release -- \
  --count 100 --workers 4 --profile-passes 1 \
  --label candidate --output artifacts/performance/candidate.json
```

Перед измерением все четыре уникальных документа читаются для прогрева. `--profile-passes`
задаёт дополнительные последовательные проходы с таймерами этапов. Основной замер выполняет
полный прогон и включает повторную загрузку шаблонов и создание реальных движков для каждого
рабочего потока. Таймеры этапов в основном прогоне отключены.

Параметры:

- `--pdf-text true/false`: включить/отключить чтение текстового слоя с независимой растровой
  проверкой. Одинаковый флаг применяется при прогреве, профилировании и полном прогоне,
  включая дочерние процессы. Без параметра используется настройка ядра.
- `--gost-fallback true/false`: разрешить дополнительную пару Tesseract `rus_gost+eng`
  и Cyrillic PaddleOCR при отказе основной пары или для шаблона, где эта пара уже помогла.
  Выбор модели для шаблона может кэшироваться; текст каждого нового PDF читается снова.
  Флаг действует одинаково при прогреве, профиле, основном прогоне и в дочерних процессах.
- `--dataset-kind raster|vector|mixed`: явная метка отдельного синтетического набора.
  Она не превращает скан в векторный PDF; фактическая ветка проверяется через provenance.
- `--expect-source ocr|pdf-text-confirmed|mixed|none`: требуемая фактическая ветка каждого
  результата. Несоответствие делает проверку неуспешной.
- `--require-provenance true`: запретить успех, если хотя бы один обработанный файл не передал
  фактические счётчики чтения. По умолчанию требование выключено для повторения старых baseline.

- `--process-workers true/false`: экспериментальный пул отдельных OCR-процессов. Каждый
  читает PDF и распознает текст тем же ядром; переименование остается в родителе. По умолчанию
  выключен: в заключительном Windows-сравнении быстрее оказались постоянные потоки.
  В process-auto число ограничено CPU и памятью. JSON содержит
  `ProcessWorkers`, `ResolvedProcessWorkers`, число запущенных/оставшихся процессов и CPU
  родителя/детей. Пик working set — сумма RSS родителя и живых детей, с повторным учетом общих
  страниц; это не уникальный объем физической RAM. После выхода процесса CPU берется из
  финального сообщения/OS, при exit-race — из последнего успешного sample с явным счетчиком.

- `--hamming-avx2 true/false`: точный SIMD-поиск соседей при подборе шаблона;
  включен по умолчанию в версии 1.3.1 после заключительного сравнения. На CPU без AVX2
  используется прежний расчёт. JSON содержит запрос `Configuration.HammingAvx2`, фактическое включение
  `ResolvedHammingAvx2` и аппаратную доступность `Environment.HammingAvx2Available`.

- `--count 100`: число PDF; `--workers 1/2/4/8`: параллельные документы; `--workers 0` —
  автоматическое значение из настроек ядра. В JSON записываются запрошенное и фактическое значения.
- `--opencv-threads 1`: явный лимит внутренних потоков OpenCV; без параметра действует настройка ядра.
- `--batch-fields true/false`: группирование OCR-полей, если поддерживается
  данным ядром; в версии 1.3.1 по умолчанию выключено, отдельные области читаются по одной.
- `--one-dnn true/false`: явно выбрать oneDNN для эксперимента, если ядро и поставленная
  нативная библиотека Paddle поддерживают этот вариант; без параметра действует значение
  фабрики ядра по умолчанию. Применимо только с `--onnx false`; при ONNX в JSON — `null`.
- `--reuse-predictors true/false`: переиспользование экземпляров вычислителя Paddle внутри
  одного рабочего потока с `--onnx false`. Без параметра действует значение ядра.
- `--known-lines true/false`: режим известных текстовых строк, если
  поддерживается ядром. Без параметра действует значение ядра по умолчанию. Один вариант
  применяется ко всем движкам при прогреве, профилировании и основном измерении; запрошенное
  и фактическое значения записываются в JSON. Включение флага не меняет настройки приложения.
- `--dedicated-workers true/false`: отдельные потоки обработки вместо асинхронных задач пула,
  если поддерживается ядром; без параметра действует значение ядра по умолчанию. Для постоянных
  Paddle-предикторов нужен стабильный поток: `false` оставлен для воспроизведения старого
  неудачного эксперимента, в котором длинный прогон получил нативные ошибки.
- `--profile-passes 0`: только прогрев и полный замер, без дополнительных профилируемых проходов.
- `--samples docs/test-samples`: папка с `verification.json`, `templates` и `scans`.
- `--keep-workdir`: сохранить созданную временную папку для осмотра.

Лимиты OpenMP/BLAS задаются **до запуска процесса**. Каждый вариант запускается отдельно:

```sh
OMP_THREAD_LIMIT=1 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
dotnet run --project tools/Performance -c Release -- \
  --count 100 --workers 4 --opencv-threads 1 --profile-passes 1 \
  --label native-one-thread --output artifacts/performance/native-one-thread.json
```

Измерения выполняют последовательно на свободной машине; параллельные сборки/тесты искажают
результат. Для сравнения старого ядра можно собрать тот же инструмент с другой ссылкой:

```sh
dotnet build tools/Performance -c Release \
  -p:CoreProjectPath=/absolute/path/to/baseline/src/Core/Core.csproj \
  -p:ArtifactsPath=/absolute/path/to/baseline-build
```

Старое ядро должно разрешать `InternalsVisibleTo` для `DocumentTextRecognition.Performance`.
Если нужен профиль этапов старого ядра, в копию добавляется только наблюдающий callback,
без изменений алгоритма. Отсутствие callback отмечается как `PhaseProfile.Instrumented=false`.

JSON сохраняет версию ОС/.NET/Tesseract, доступные процессоры и ограничения cgroup,
настройки потоков, хеш ядра и набора, время обработки и CPU, максимальные наблюдаемые RSS
и число потоков (опрос каждые 100 мс), число правильных переименований и подробности ошибок.
`Projected8000Minutes` — линейная экстраполяция. Поле `Measured8000Minutes` содержит фактическое
время только при `Dataset.Count=8000`; в остальных случаях оно равно `null`. Вложенные стадии
`crop.render` и `crop.prepare` входят в `crop`, а `paddle.detect` и `paddle.recognize` —
в `ocr.PaddleOCR`: складывать вложенные стадии повторно нельзя.

Отдельный генератор проверяет более разнообразный набор: восемь вариантов содержимого,
200/250/300 dpi, поворот и небольшой перекос, разные обозначения и геометрия чертежей.
Он использует общедоступные генераторы из тестового проекта, поэтому сборка включает зависимости
тестов. Целевая папка должна быть пустой. Все ожидаемые имена задаются до OCR; ошибочный результат
или отказ сохраняется в `verification.json` и завершает генератор с ошибкой. Неудачные файлы
из набора автоматически не исключаются.

```sh
dotnet run --project tools/PerformanceSamples -c Release -- artifacts/performance-diverse-samples
dotnet run --project tools/Performance -c Release -- \
  --samples artifacts/performance-diverse-samples --count 48 --workers 0 --profile-passes 1 \
  --label diverse --output artifacts/performance/diverse.json
```

Это дополнительная проверка изменения размеров входа и текста, а не замена замера на реальных
производственных документах. Если генератор завершился с ошибкой, её необходимо изучить перед
запуском измерения; нельзя выдавать результат на оставшихся положительных файлах за весь набор.

В версии 1.3 модели выполняются через ONNX Runtime по умолчанию; `--onnx false` задаёт
прежний native Paddle для контрольного сравнения.
`--onnx-models artifacts/onnx-models` задаёт каталог `det.onnx` и `rec.onnx`, полученных
скриптом `tools/OnnxPerformance/convert_models.py`; без пути используется `ocr/onnx` рядом
со сборкой ядра. Модели не скачиваются при запуске; проверенные графы входят в обычную сборку.
`--known-lines false` отключает штатный путь одиночных строк для отдельного сравнения.
В JSON записываются запрошенный `Onnx` и фактический `ResolvedUsesOnnx`; настройки oneDNN
и повторного использования Paddle-предикторов для ONNX неприменимы и отражаются как `null`.
ONNX и `--known-lines` включаются независимо, чтобы сравнивать каждый вариант отдельно.

```sh
dotnet run --project tools/Performance -c Release -- \
  --count 100 --workers 4 --known-lines false --onnx true --onnx-models artifacts/onnx-models \
  --label onnx-experimental --output artifacts/performance/onnx-experimental.json
```

Для повторного замера старого растрового набора не заменяйте его PDF или `verification.json`:

```sh
dotnet run --project tools/Performance -c Release -- \
  --samples docs/test-samples --count 8000 --workers 0 --pdf-text true \
  --dataset-kind raster --expect-source ocr --require-provenance true \
  --label raster-8000 --output artifacts/performance/raster-8000.json
```

Векторный набор с реальными текстовыми объектами хранится в отдельной папке с собственными
шаблонами и заранее заданным `verification.json`. Для него используются `--dataset-kind vector`
и `--expect-source pdf-text-confirmed`. Время векторного набора нельзя выдавать за ускорение
старых растровых сканов. Все примеры остаются синтетическими, пока не проверены реальные файлы.

`Dataset.VerificationManifestSha256` фиксирует ожидаемые имена отдельно от хешей входных PDF.
Если у входа указан `Sha256`, инструмент проверяет его до замера. `ExcludedNonRequiredSamples`
явно перечисляет примеры, не включённые в положительный throughput-набор; отказы ГОСТ проверяются
отдельным полным accuracy-набором и не превращаются в успех от исключения из замера.

`Provenance` суммирует только результаты основного измерения, без прогрева. Сохраняются число
попыток/подтверждений PDF-text, изображения полей, переданные Tesseract/Paddle/EasyOCR, страницы
и вызовы подбора шаблона, попытки/успехи пары ГОСТ и группировка по источнику и статусу. Пакет из трёх полей даёт
три `PaddleReads`; повтор после неподтверждённого результата учитывается снова. Поэтому
PDF-text с растровой проверкой не объявляется запуском двух OCR на каждом документе.

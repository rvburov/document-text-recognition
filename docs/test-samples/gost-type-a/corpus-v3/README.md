# Новый корпус с двумя растеризаторами

V3 фиксируется до нового обучения. Предыдущие 150 изображений Pillow уже использовались для оценки v2; их результат остаётся историческим, а самостоятельная итоговая выборка v3 содержит новые значения. Этот корпус проверяет тот же закреплённый шрифт ГОСТ типа А и не доказывает перенос на другой шрифт.

| Часть | Комплекты designation + name | Разных строк | Skia PNG | Pillow PNG |
|---|---:|---:|---:|---:|
| Обучение | 300 | 600 | 600 | 600 |
| Выбор модели | 60 | 120 | 120 | 120 |
| Итоговая оценка | 30 | 60 | 60 | 60 |

Полные строки и четырёхбуквенные префиксы не повторяются между частями, основным корпусом v1, дополнением v2 и прежними контрольными примерами. Все изображения одного текста находятся в одной части. Ожидаемые значения берутся из заранее заданных слов и чисел с фиксированной строкой-инициализатором; предсказания OCR не используются. Эталоны сохраняют исходный Unicode, включая `ё`, латиницу и регистр. Отдельная проверка конечного имени файла должна учитывать прежние явно описанные правила приложения, а не менять напечатанный эталон.

Для каждого изображения manifest явно задаёт `Renderer`, DPI (250/300/325), физическую высоту букв (3,5/5 мм), перекос (0/±0,8°), поля (8/16 пикселей) и фон (245/250/255). Оба растеризатора одного текста получают одинаковые параметры. Фактические PNG сравниваются по SHA-256, число разных и совпавших пар записывается в `lines.json`. Это реальные вызовы Skia и Pillow, а не две метки одного изображения. В обучении покрыты все 33 заглавные русские буквы, цифры, точки и дефисы; латиница встречается в смешанных наименованиях. `Ё` располагается в словах, поскольку текущая грамматика обозначений её не допускает.

Линейные вырезки не содержат рамок: чёрная рамка исказила бы границы строки при подготовке Tesseract LSTMF. Проверки рамок выполняются на полных PDF после стандартной подготовки областей. Серый фон остаётся светлее порога 200, которым определяется текст. Наличие глифов, отсутствие обрезания, режим L8 и хеши фиксируются при генерации.

`manifest.json` содержит хеши отдельных `train.json`, `development.json`, `evaluation.json`. Тренеру передаются только первые две части. Итоговые значения и изображения не используются при выборе checkpoint, PSM или предварительной обработки. По умолчанию они сохраняются в отдельной папке, чтобы рекурсивный сбор обучающих файлов их не захватил.

```bash
python3 tools/GostCorpus/prepare_v3.py
python3 tools/GostCorpus/render_v3.py --split train
python3 tools/GostCorpus/render_v3.py --split development
# Отдельное хранилище итоговой оценки; не передавать в обучение:
python3 tools/GostCorpus/render_v3.py --split evaluation
```

При повторном запуске `prepare_v3.py` проверяет frozen JSON и отказывается переписывать отличающиеся значения. Рендер требует пустой выходной папки. Отчёты распознавания добавляются после выбора модели; само создание изображений не является успешным OCR.

# Проверка выбранной модели ГОСТ V3 на PDF

Здесь сохранена точная копия окончательного прогона `artifacts/gost-veto-final`: реальный `DocumentReader.Read` со штатными движками, моделью ГОСТ и проверкой текстового слоя PDF. Модель Tesseract выбрана по development до открытия итоговой выборки; её SHA-256 — `c92b7c889f0bd4fb07ca90148c011be7a1865be2b8bba036fa1a86d875a5add0`. Хеш отчёта выбора — `fef34d30a48622f87da65ba9c66d6715642d37714e1a2c7b78e17568cf515dc8`. Выбранная политика: PSM13 с сохранением исходных пикселей обозначения и полями 8 пикселей, PSM6 для наименования. Модель и напечатанные эталоны после открытия итоговой выборки не менялись.

После первого PDF-прогона уточнён путь независимой проверки текстового слоя: дополнительный OCR может подтвердить текст, если первый не дал уверенного валидного ответа, противоречащего этому тексту. Такой конфликт сохраняет отказ. Поэтому результаты PDF ниже — повторная регрессионная проверка процесса распознавания, а не новый слепой замер всей системы. Отдельный однократный замер выбранного Tesseract на 120 новых строках дал 107 точных ответов: 51/60 обозначений и 56/60 наименований. Это результат одного движка на строках, а не число принятых PDF.

| Проверка | Точно прочитано | Отказ | Принято неверно |
|---|---:|---:|---:|
| Прежний пример ГОСТ: обычный, 90° и перекос 1,2°; два режима KnownLines |4/6|2|0|
| Новые векторные PDF |5/8|3|0|
| Новые PDF только с изображением |2/8|6|0|

Исходный `УИЕС.468732.271 Плата УПЧ 1489 МГц` теперь точно прочитан при обычной ориентации и перекосе 1,2° в обоих режимах. При 90° Tesseract выдаёт `УЙЕС`, Paddle — `УИЕС`; документ получает отказ. Полные записи находятся в [current-profile-verification/end-to-end/verification.json](current-profile-verification/end-to-end/verification.json). Все попытки обычной и специализированной моделей сохранены отдельно: 24 записи полей, их PNG, исходные ответы и уверенность, координаты и `SourceTrace`. Пример исходного PDF и его шаблон — в `current-profile-verification/fixture`.

[pipeline-v3/verification.json](pipeline-v3/verification.json) содержит все 16 новых чтений, включая отказы. Для каждого из 8 комплектов папка `pipeline-v3/evaluation-XXX` сохраняет векторный и растровый PDF, нейтральный шаблон с координатами и вырезки каждой диагностической попытки. Один шаблон применяется к соответствующей паре документов. Ожидаемые значения взяты из зафиксированного manifest; распознаватель получает только PDF и шаблон.

У векторных успешных документов `SourcePath=pdf-text-confirmed`: текстовый слой подтверждён независимым чтением изображения Paddle или Tesseract; уверенное противоречие другого уже выполненного чтения не игнорируется. Для успешных сканов `SourcePath=ocr`; оба OCR-движка согласовали поля. Записаны фактические счётчики обращений к движкам и SHA-256 исходных PDF/шаблонов. Содержимое документов проверено на неизменность. Ожидаемое имя файла учитывает заранее объявленные правила приложения: объединение пробелов, `ё→е`, `Ё→Е`, а при отсутствующем поле типа — `Спецификация`. Напечатанные эталоны отдельно сохранены без этих преобразований.

Часть новых отказов связана с Paddle: например, `Оптопара` прочитана как `Onтопара` или `Onmonapa`, а буквы в обозначениях перепутаны с цифрами. Корректный ответ одного движка не подставляется вместо независимой сверки. Поэтому эти результаты подтверждают реальные положительные чтения, но **не означают успешное распознавание всех новых документов**. Пороги, эталоны и буквенные замены по результатам этих 8 случаев не подбирались.

Проверки требуют хотя бы одного точного векторного и одного точного растрового результата, ни одного ошибочно принятого ответа и обязательного точного чтения прежнего примера без поворота при штатной настройке. Все остальные отказы остаются в отчёте. Окончательный запуск завершился `3/3 PASS`: 16 новых PDF, 6 прежних вариантов и отдельная проверка базовых профилей на вырезках. Последняя записана в `current-profile-verification/direct-fields`: базовая пара без маршрутизации специализированной модели дала 2/8 точных полей и 0/6 полных сочетаний. Эти числа нельзя смешивать с результатами полного `DocumentReader` или одиночного обученного Tesseract.

[evidence-manifest.json](evidence-manifest.json) содержит хеши всех 172 файлов, скопированных из окончательного прогона, хеш TRX и результаты трёх тестов. Все 16 новых исходных PDF, их шаблоны и разметка сверены с хешами в отчёте. Исходные пять демонстрационных PDF, три шаблона, три sidecar и прежний `verification.json` побайтно совпадают с коммитом `7a6aa36db302387b28c2580c7b326301a7019461`; все три контрольные суммы PDF внутри sidecar также совпадают. Новый выбор модели по ошибкам этих данных потребует другой независимой выборки.

# Раздельная выборка ГОСТ типа А

Это **план и заранее заданные эталоны**, а не результат успешного OCR. Здесь нет новых изображений, обученной модели или измеренной точности. Текущие опубликованные примеры `УИЕС.468732.271` / `Плата УПЧ 1489 МГц` / `Плата Epcos USB` уже использовались при исследовании ошибок и остаются набором регрессионных проверок.

После фиксации manifest создан первый набор строк в `artifacts/gost-corpus`: 600 обучающих изображений (136 разных текстов), 76 изображений для выбора настроек (36 текстов) и 150 итоговых (72 текста). В [rendered-lines.json](rendered-lines.json) записаны версии, контрольные суммы metadata и проверки целостности. Это подтверждает генерацию, но ничего не утверждает о качестве модели. Команды генерации и формат PNG/GT описаны в [tools/GostCorpus](../../../../tools/GostCorpus/README.md).

`manifest.json` фиксирует 112 новых комплектов полей: 64 для обучения, 16 для выбора настроек и 32 для итоговой оценки. Обозначения, полные наименования и четырёхбуквенные префиксы не пересекаются между частями. Десятичные группы получены из SHA-256 с фиксированной строкой-инициализатором. В обозначениях предусмотрены точки, дефисы исполнения и коды `СБ`, `Э3`, `ПЭ3`; наименования содержат кириллицу, латинские названия и одну или две строки. Стандартные названия видов документа могут повторяться: это ограниченная предметная лексика, её нельзя считать независимым словарным испытанием.

Все изображения, PDF, отдельные строки и изменения одного комплекта полей принадлежат одной части. Нельзя отправить оригинал в обучение, а его повёрнутую или зашумлённую копию — в итоговую оценку. Эталоны не выводятся из предсказаний моделей; содержимое файлов и шаблонов не должно использоваться как подсказка ожидаемого ответа. Имена будущих файлов содержат только нейтральный `Id`.

Используется прежний закреплённый шрифт ГОСТ типа А, его SHA-256 записан в manifest. Это **не проверка на другом шрифте**: другой разрешённый шрифт и реальные пользовательские PDF пока не включены. Разделены текстовые значения, профили DPI и способы рисования. Для итоговой оценки предусмотрены Pillow/FreeType и PDFium с встроенным в PDF шрифтом, для обучения — SkiaSharp. Эти способы имеют общие низкоуровневые компоненты; такое разделение не означает полной независимости растеризаторов. Основные физические высоты букв совпадают с рабочими формами, а дополнительные размеры 2,5 и 7 мм проверяются отдельно на вырезках. Две строки высотой 7 мм нельзя обрезать маленькой ячейкой ради выполнения теста.

## Парные PDF и сохранённые координаты

Для каждого итогового комплекта планируются две версии одной страницы: векторный PDF с достоверным `ToUnicode` и PDF, содержащий только растр этой страницы. Они должны иметь одинаковый физический размер, расположение полей и сохранённые нормированные координаты. Векторную версию создаёт `PdfTextFixtures` с точным встроенным шрифтом; отдельный помощник добавляет форму и сохраняет образец. Растровую версию получают из отрисованного вектора без повторного набора текста. Координаты, номер страницы, размеры и хеши будут записаны рядом с образцами. Шаблон содержит посторонние демонстрационные значения и задаёт только расположение полей.

Такое сравнение отделяет ошибки чтения изображения от ошибок текстового слоя. Для скана ожидается отсутствие слоя; для вектора — точные символы внутри выбранной области. Скрытый, невидимый, устаревший или неверно сопоставленный текст проверяется отдельными отрицательными примерами и не считается успешным распознаванием положительного корпуса. Наличие текста в PDF само по себе не подтверждает его соответствие видимым символам.

Основная оценка проводится на чистых, читаемых страницах. Повороты, перекос ±1,2° и JPEG-сжатие входят в отдельный стресс-набор; они не заменяют проверку чистого ввода. Перед OCR необходимо проверить наличие глифов в закреплённом шрифте, отсутствие обрезания, сохранённые координаты и отсутствие целевых значений за пределами выбранных полей. Некорректно нарисованный образец считается дефектом генератора, а не успехом или отказом OCR.

## Как оценивать результат

В отчёте отдельно записываются **точное распознавание / отказ / ошибочно принятый ответ** для каждого поля и документа. Сверка сохраняет все буквы, цифры, знаки и исходный алфавит Unicode; допускается только заранее указанное объединение пробелов и переносов строк. Отказ не выдаётся за успешное чтение. Положительный тест требует точного совпадения всех полей, формирования ожидаемого имени и неизменности содержимого PDF после переименования. Проверки «нет неправильных ответов» сами по себе недостаточны.

На `development` разрешено выбирать модель и параметры. Итоговый `evaluation` проверяется после фиксации кандидата и его хеша. Если ошибки этого набора использованы для настройки, он становится набором разработки; для следующего независимого заявления нужна новая заранее зафиксированная оценочная часть. Существующие примеры и текущие пять демонстрационных PDF не перезаписываются.

Воспроизведение эталонов без установки графических библиотек и без запуска OCR:

```bash
python3 tools/GostCorpus/prepare_manifest.py --check
```

Команда без `--check` создаёт только `manifest.json`. Рендеринг и обучение этим скриптом не выполняются. Перед первой генерацией изображений следует сохранить текущий SHA-256 manifest в отчёте эксперимента.

# Полный Windows-замер 1.4.0

Каждый прогон действительно обработал и переименовал **8000 PDF**. Во всех случаях
имя совпало с независимым эталоном, содержимое осталось прежним: проверены 8000 SHA-256,
ошибок и пропусков нет. На этих стендах оба результата укладываются в цель 15–20 минут.

| Набор | Время 8000 PDF | CPU-время | Наблюдаемый пик RSS | Процессор стенда |
|---|---:|---:|---:|---|
| Растровые сканы | **17:31,10** | 3416,17 с | 1,73 ГиБ | AMD EPYC 9V74 |
| Векторные PDF с текстом | **17:16,89** | 4111,39 с | 1,80 ГиБ | AMD EPYC 7763 |

Оба стенда: Windows Server 2022, .NET 10, **4 доступных логических процессора**,
автоматически выбраны восемь постоянных рабочих потоков. OCR-процессы выключены,
ONNX, чтение известных строк, AVX2, текст PDF и резервная модель ГОСТ включены штатно.
RSS опрашивается каждые 100 мс; короткие пики между опросами могут не попасть в отчёт.

## Что именно проверено

Каждый набор содержит **четыре разных одностраничных синтетических документа**,
повторённых до 8000 файлов. Для сканов сохранены прежние четыре положительных PDF
и три шаблона; векторный набор содержит четыре новых документа и два шаблона.
Наборы и CPU различаются: эти числа не измеряют ускорение одной и той же страницы
от замены одного алгоритма другим. Они подтверждают время полного конвейера на
раскрытых тестовых данных. Скорость и доля распознавания 8000 разных пользовательских
документов этим замером не установлены.

Время включает инициализацию новых рабочих OCR-движков, загрузку шаблонов, перечисление,
подбор шаблона, чтение, журналирование и переименование. Создание тестовых копий,
отдельный предварительный прогрев и итоговая проверка SHA-256 выполняются вне замера.
Все документы читаются заново. Между файлами сохраняется только выбор модели для шаблона.

| Фактически выполнено | Сканы | Векторные PDF |
|---|---:|---:|
| Обработано и переименовано | 8000 | 8000 |
| Неверных имён / пропусков / ошибок | 0 / 0 / 0 | 0 / 0 / 0 |
| Подтверждён текст PDF | 0 | 8000 |
| Вызовы Tesseract по изображениям полей | 18000 | 32 |
| Вызовы PaddleOCR по изображениям полей | 18000 | 28048 |
| Принято специализированной парой ГОСТ | 0 | 4000 |
| Отсутствует или повреждена трассировка | 0 | 0 |
| Оставшиеся рабочие OCR-процессы | 0 | 0 |

В сканах результат подтвердили два растровых OCR. Во всех векторных документах
использован текст сохранённых областей и фактическая проверка их изображения;
это не заявление о выполнении обоих OCR на каждом таком файле. Пакет из нескольких
полей считается как несколько чтений. Повторные попытки также входят в счётчики.

Замер выполнен на `7f8cddb`. Последующее исправление `e7b8dc8` меняет только тест
подсчёта резервных попыток на Windows и документацию; исходники программы, модели,
версия и инструмент замера совпадают. Обычные
[проверки `e7b8dc8`](https://github.com/rvburov/document-text-recognition/actions/runs/44410792280)
зелёные: Linux Core 586 пройдено / 1 необязательный пропуск, App 48/48;
Windows OCR/PDF/ГОСТ 174 пройдено / 1 необязательный пропуск; опубликованная поставка
и процессный smoke прошли. Необязательные пропуски относятся к дополнительному набору
из 48 документов, не указанному в CI. Локально с этим набором прошли все 588 тестов Core.

Этот throughput-набор не измеряет точность на сложных сканах ГОСТ. В отдельном
[полном тесте ГОСТ](../../test-samples/gost-type-a/selected-v3/README.md) точно прочитаны
5/8 векторных и 2/8 растровых документов; остальные отклонены, неверных принятий нет.
Однократная оценка отдельно дообученного Tesseract дала 107/120 точных строк; это другой
уровень проверки. На исходном PDF пользователя качество ещё не проверено.

## Повторение на ПК

Из корня репозитория в Git Bash, при установленном .NET SDK из `global.json`:

```bash
dotnet run --project tools/Performance -c Release -- --samples docs/test-samples --count 8000 --workers 0 --pdf-text true --gost-fallback true --dataset-kind raster --expect-source ocr --require-provenance true --profile-passes 1 --output artifacts/raster-8000.json
dotnet run --project tools/Performance -c Release -- --samples docs/test-samples/vector-performance --count 8000 --workers 0 --pdf-text true --gost-fallback true --dataset-kind vector --expect-source pdf-text-confirmed --require-provenance true --profile-passes 1 --output artifacts/vector-8000.json
```

Прежний [замер 1.3.1](../final-windows/windows-final-8000.json) — отдельный исторический
результат: 20:38,74. Его входные PDF и отчёт не заменялись.

# Реальные документы ЕСКД: регрессионный корпус

Настоящие PDF конструкторской документации (схемы Э3, перечни ПЭ3, сборочные чертежи СБ,
спецификации, чертежи деталей, ТУ) из открытых репозиториев GitHub. Тест
`RealDocumentTests` читает их тем же кодом, что и программа: шаблон с сохраненными областями,
совмещение, два OCR, сверка, имя файла. Он запускается в каждой проверке на GitHub
(`.github/workflows/checks.yml`) и при обычном `dotnet test`.

## Что проверяется

Каждый документ читается в трех вариантах:

| Вариант | Что это |
| --- | --- |
| `vector` | исходный PDF: текстовый слой подтверждается распознаванием изображения, иначе OCR |
| `scan300` | страница с основной надписью без текстового слоя, серый лист 300 dpi, JPEG 90 |
| `scan200-skew` | 200 dpi, перекос 0,6 градуса, размытие, шум, JPEG 75 |

Правила теста:

- **неверное принятое значение всегда проваливает тест** (главное требование программы);
- отказ допустим, но если вариант в базовой линии (`baseline` в `manifest.json`) читался точно,
  а теперь отказ, это регрессия. На Linux в проверках GitHub регрессия проваливает тест
  (`DTR_REAL_DOCS_BASELINE=enforce`), на Windows попадает только в отчет;
- если вариант стал читаться точно, тест пишет «Улучшение» и подсказывает обновить базовую линию.

Отчет `real-documents-report.json` (переменная `DTR_REAL_DOCS_OUTPUT`) содержит по каждой
графе ответы обоих движков, уверенность, причину отказа и вырезку, которую видел OCR, а также
сводку точности каждого движка по графам. В проверках GitHub он лежит в артефакте
`tests-and-pdf-samples`.

## Эталоны

Значения граф заданы по самому документу (текстовому слою и изображению), а не по ответам OCR,
и записаны в форме, которую дает программа:

- обозначение: код документа слитно (`АБВГ.112345.001 ПЭ3` → `АБВГ.112345.001ПЭ3`), латинские
  буквы-двойники как кириллица;
- наименование: строки через пробел, «е» вместо «е с точками», дефис вместо тире;
- тип: из справочника типов; если типа в основной надписи нет, шаблон помечен «Тип отсутствует»
  и ожидается «Спецификация» (правило программы);
- `mustRefuse`: верного имени по правилам программы нет (пустая графа обозначения, в ней
  наименование изделия, только код). Любое принятое значение считается ошибкой.

Многие студенческие обозначения не соответствуют ГОСТ 2.201 (`НВЦТ.ДТН.0000.100 СБ`,
`П8.21932.0 СБ`). Программа обязана отказаться от них, а не придумать похожее значение.

## Файлы

- `documents/` - PDF под лицензией MIT, хранятся в репозитории; тексты лицензий в `licenses/`.
- `external/` - остальные документы. Лицензии у них нет, поэтому в репозиторий они не
  копируются: в `manifest.json` записана ссылка на конкретный коммит автора и SHA-256.
  Тест скачивает их при `DTR_REAL_DOCS_FETCH=1` и проверяет хеш. Папка в `.gitignore`.
  Если автор удалит репозиторий, документ будет пропущен с причиной в отчете.

Источник каждого документа указан в полях `repository` и `source` манифеста.

## Запуск

```bash
DTR_REAL_DOCS_FETCH=1 DTR_REAL_DOCS_OUTPUT=/tmp/real-docs \
  dotnet test tests/Core.Tests -c Release --filter RealDocumentTests --logger "console;verbosity=detailed"
```

```powershell
$env:DTR_REAL_DOCS_FETCH = '1'; $env:DTR_REAL_DOCS_OUTPUT = "$env:TEMP\real-docs"
dotnet test tests/Core.Tests -c Release --filter RealDocumentTests --logger "console;verbosity=detailed"
```

`DTR_REAL_DOCS_ONLY=03-,26-` - прочитать только документы с такими началами id.

## Свои документы

Свои PDF (например, документы предприятия, которые нельзя публиковать) подключаются отдельной
папкой с таким же `manifest.json`: `DTR_REAL_DOCS_DIR=D:\Проверка\Документы`. В git такая папка
не попадает. Запись документа:

```json
{
  "id": "01-plata-upch",
  "file": "Плата УПЧ.pdf",
  "page": 0,
  "typeAbsent": false,
  "regions": [
    { "role": "Designation", "bounds": { "x": 0.53, "y": 0.81, "width": 0.4, "height": 0.04 } },
    { "role": "Name", "bounds": { "x": 0.43, "y": 0.86, "width": 0.3, "height": 0.05 } },
    { "role": "Type", "bounds": { "x": 0.43, "y": 0.91, "width": 0.3, "height": 0.03 } }
  ],
  "expected": { "designation": "УИЕС.468732.271", "name": "Плата УПЧ 1489 МГц", "type": "Схема электрическая принципиальная" }
}
```

Области проще всего взять из редактора шаблона: откройте PDF в программе, выделите поля,
сохраните и скопируйте `regions` и `typeAbsent` из файла `Плата УПЧ.pdf.template.json`.
Поле `template` с id другого документа проверяет чтение по общему шаблону формы.

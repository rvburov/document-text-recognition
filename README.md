# Распознавание текста документов

Программа для Windows: читает в штампе скана конструкторского документа обозначение, наименование
и тип документа и переименовывает PDF-файл в «Обозначение Наименование Тип документа.pdf»,
например «АБВГ.466229.001 Плата Спецификация.pdf». Файлы только переименовываются на месте,
содержимое не меняется, ничего не удаляется.

## Как работает

- **Шаблоны.** В папке шаблонов лежат PDF-образцы документов, где поля штампа обведены цветными
  рамками: синяя (обозначение), зеленая (наименование), желтая (тип документа) или одна красная
  вокруг всех трех полей. Программа сама подбирает шаблон к каждому скану и совмещает их.
- **Два способа распознавания со сверкой.** Каждое поле читают Tesseract и PaddleOCR; имя
  ставится, только если оба прочитали одинаково. Иначе файл пропускается с причиной: лучше
  оставить старое имя, чем дать неверное.
- **Тип документа не написан на скане** (поле пустое): в имя ставится «Спецификация».
- **Статусы файлов:** «Переименован», «Имя уже верное», «Пропущен» (с причиной), «Ошибка»
  (сбой программы). Результат можно скачать в Excel, CSV или текст.
- Все работает на этом компьютере, интернет не нужен; сканы никуда не отправляются.

## Устройство репозитория

```
src/Core      распознавание: рамки шаблона, совмещение, Tesseract и PaddleOCR, имя файла, прогон
src/App       окно программы (Avalonia), выгрузка, обновление из папки обновлений, удаление
src/Setup     установщик «Распознавание текста документов-Setup.exe»
src/Common    общее для программы и установщика: пути, настройки, журнал, ярлыки
src/Ui        оформление по макету: цвета, шрифты, кнопки, поля, полоса прокрутки, значки
ocr/tessdata  языковые данные Tesseract (rus, eng)
tests         тесты ядра и окна (настоящее распознавание на синтетических сканах)
scripts       build.ps1: сборка на ПК; ci-ocr-deps.sh: компоненты для проверок на GitHub
docs          документация и макет
```

Проверки на GitHub (`.github/workflows/checks.yml`): тесты на Linux и сборка установщика на Windows.
